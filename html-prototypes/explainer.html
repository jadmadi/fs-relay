Explainer

Press play: eight scenes, two and a half minutes, the whole system.

  • Sharing a directory usually means NFS or SMB:
  • root-run daemons, firewall rules, slow mounts.
  • fs-relay mounts a remote directory as a local filesystem.
  • About ten times faster — with two commands and no root.
  • Two binaries. First, build them.
  • Serve a directory on the storage host.
  • Mount it on every client.
  • One connection per mount. Now it is a normal directory.
  • Each mount keeps one connection to the server.
  • Calls flow up; results flow back down.
  • Events — evictions, lock releases — ride the same socket.
  • Large bytes leave for a separate raw connection.
  • By default: one websocket, calls and events together.
  • Each call carries an id; the server echoes it back.
  • -post instead: one request per call, plus a join stream.
  • Same envelope both ways. Pick one per mount.
  • Unpacking 5,868 files: s3fs takes 204 seconds.
  • NFS through FUSE: 108. kvfs: 26.
  • fs-relay: 15 and a half. Thirteen times faster than s3fs.
  • Numbers from the repo's own benchmark tables.
  • Mounts cache everything: names, attributes, small files.
  • Every change pushes an eviction to all mounts.
  • The writing mount keeps the name; others drop it.
  • Missed news? Rejoin replays it. Names heal in a second.
  • One server lock table per namespace.
  • SQLite locks three byte ranges; the table counts them.
  • A conflict returns EAGAIN — the mount waits and retries.
  • Release wakes every waiter. Proven: 200 rows, both mounts, integrity ok.
  • Bytes past a threshold skip the envelope.
  • The kernel splices: file to pipe to socket to FUSE.
  • No copies through the server process. Failures retry once.
  • Two commands. No root. That's fs-relay.
