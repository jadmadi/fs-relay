Wire

FlatBuffers is the only filesystem wire. Method names are the go-fuse methods, lowercased, so a relay is a thin translation.

How do mount and server talk? One FlatBuffers envelope over two transports: a single websocket by default, or one POST per call with -post. Large bytes leave this wire for the raw path.

The envelope

  • Content type application/x-flatbuffers, file identifier FSR1. Schema: internal/wire/fsrelay.fbs.
  • One buffer is one envelope. File bytes ride a byte vector; one call carries at most 1 MiB.
  • params.namespace must equal the URL segment, or the request is refused.
  • Empty strings and empty byte vectors are absent. A numeric zero is present — and valid still says which setattr fields count, so a size or owner of zero is applied.
  • A name of ., .., or one containing / or NUL is EINVAL.
  • Under FSR1, field identity is declaration order: a table only grows by appending a field. Anything else needs a new identifier.

Websocket transport (default)

  • The client sets a nonzero id on each call; the server copies it onto every message for that call. Calls overlap.
  • A filesystem failure carries the id and the error. A non-errno fault carries the id and a fault string, and the socket stays up.
  • A body that is not a call, an id of 0, a repeated id, or a namespace mismatch closes the socket.
  • No join call: the server's first message carries the client id. The server pings every 2s; the mount answers.

POST transport (-post)

  • Each call is its own POST /fs/<namespace>. The response is the result, one envelope, with a Content-Length. No request id — the HTTP exchange is the correlation.
  • The client first sends join. That response stays open for the life of the mount: Content-Type: application/x-flatbuffers, chunked. Each event is one chunk holding a little-endian uint32 length and then one envelope.
  • A length above the body limit closes the stream. The first event carries the signed client id; later events are evictions or a lock release.

Client identity

The server names a mount with a UUIDv7 and returns <uuid>.<signature>. The signature is HMAC-SHA256 of the uuid keyed by the secret, URL-safe base64, no padding. A rejoin presents the whole string; the server re-signs and accepts only a match. Anything else is 400. The secret itself never appears in a response, a client id, or a URL.
