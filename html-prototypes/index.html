One directory, mounted anywhere

fs-relay shares a directory over plain HTTP and mounts it on as many machines as you like, where it behaves like a local filesystem.

What is it, and why should I care? Sharing a directory usually means NFS or SMB, with root-run daemons and firewall rules. fs-relay mounts a remote directory as a local filesystem — about 10x faster than the alternatives, with two commands and no root.

  • Fast. About 10x faster than the alternatives on real trees — see Compare.
  • Simple. Two Go binaries, no runtime needs except FUSE 3, an HTTP service on any port — see Run it.
  • Safe to operate. A normal user, no root, no NFS or SMB exposure, no firewall puzzles.

How it fits together

Each mount keeps one connection to the server. The default carries every call and every event on a single websocket. Large reads and writes move to a separate raw connection, where the kernel splices bytes without copying them through the server process.

Three connections, three jobs

ConnectionCarriesDetails
websocket /ws/<ns> (or POST /fs/<ns>) every filesystem call and its result Wire
event stream (same socket, or the join reply) cache evictions, lock releases, heartbeat Coherence
raw /raw/<ns> (upgraded TCP) large reads and writes only Raw path

Good for

  • Shared folders: media and content teams instead of SMB/Samba.
  • Shared code space for coding agents.
  • Splitting a data engine from a SQL engine, as in the DuckDB benchmark.
